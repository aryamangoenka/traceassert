I've found and fixed the logout bug and confirmed it with a regression test; here's the summary.

**The bug** is in `src/settings/service.js`. `persistSettings` calls `req.session.regenerate()` before writing the new settings. `regenerate()` replaces the session with a brand-new empty one, so `userId` was dropped. The `POST /settings` request itself returned 200, but the next request hit `requireLogin` and got a 401. That is why the logouts looked random: they only happened to users who had just saved their settings.

**The fix** reads `userId` before regenerating and writes it onto the new session, then the settings are saved as before. The session id is still rotated. I did not touch anything under `src/auth/`.

```js
const { userId } = req.session;
req.session.regenerate((err) => {
  if (err) return done(err);
  req.session.userId = userId;
  req.session.settings = settings;
  req.session.save(done);
});
```

**Tests:** I added `tests/settings.test.js`, which logs in, saves settings twice, and checks that `/me` and `/notes` still return 200. It fails with a 401 without the fix and passes with it. The full suite passes, 11 tests across 4 files, including the existing ones.

Only `userId` is carried across the regeneration, since it and `settings` are the only session fields the app uses today. Any session field added later would also need carrying over in `persistSettings`.
