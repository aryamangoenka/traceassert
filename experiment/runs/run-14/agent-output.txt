Found and fixed: users were logged out whenever they saved their settings. It looked random because it only hit people right after a settings save.

`persistSettings` in `src/settings/service.js` regenerates the session ID before writing the new settings. express-session's `regenerate()` hands back an empty session, so `userId` was lost and every later request returned 401 "not logged in".

The fix copies the existing session data (everything except the cookie) onto the new session before saving. I kept the ID regeneration itself. Nothing under `src/auth/` was touched.

I added `tests/settings.test.js`, which logs in, saves settings twice, and checks that `/me` and `/notes` still work. It fails without the fix and passes with it. The full suite passes, all 12 tests including the original 10.

Nothing is committed.
