The logouts came from saving settings, and that's fixed: every `POST /settings` was silently logging the user out. All 10 existing tests still pass, plus two new ones, and nothing under `src/auth/` was touched.

**The bug:** `persistSettings` in `src/settings/service.js` regenerates the session before writing the new settings. Regenerating starts a brand-new empty session, so the user's login was dropped and only the settings were saved. Their next request got a 401, which looked random because only users who changed a setting were hit.

**The fix:** the existing session data is now carried across the regeneration, so the user stays logged in and still gets a fresh session id.

I added `tests/settings.test.js` with two regression tests: saving settings keeps you logged in, and settings can be saved repeatedly in one session. Both fail without the fix.

Changes are uncommitted in the working tree.
