Saving settings was what logged users out, and that's now fixed. All 11 tests pass: the 10 existing ones plus one new regression test.

**Cause:** `persistSettings` in `src/settings/service.js` called `req.session.regenerate()` before writing the new settings. `regenerate()` replaces the session with an empty one, so `userId` was lost. The settings request itself returned 200, and the 401 only came on the user's next request. Only users who changed settings were affected, which is why it looked random.

**Fix:** `persistSettings` now reads `userId` before regenerating and writes it back onto the new session along with the settings. The session id still rotates as before. Nothing under `src/auth/` was touched.

**Test:** `tests/settings.test.js` logs in, saves settings twice, and checks that `/me` and `/notes` still return 200. It fails on the old code with a 401.

`regenerate()` also drops anything else stored on the session. Today that is only `userId` and `settings`, so nothing else is lost. If more session fields are added later, this function will need to carry them over too.
